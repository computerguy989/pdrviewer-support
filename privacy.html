01 Overview

PDR Viewer is built to run entirely on your own device. It doesn’t have a server, doesn’t ask you to create an account, and doesn’t collect analytics, usage statistics, advertising identifiers, or crash reports of any kind. Almost everything the app does — decoding telemetry, building lap comparisons, syncing video, computing stats — happens locally on your Mac or iPad and never leaves it.

The one feature that can send data off your device is the optional AI coaching summary, and even that only runs if you turn it on and provide your own API key. The sections below explain exactly what that involves.

02 The telemetry files you open

When you open a track map file or a session recording, PDR Viewer reads and decodes it on your device to build lap comparisons, charts, and stats. This includes GPS coordinates, speed, and other channels recorded by your Performance Data Recorder, along with the video itself.

None of this is uploaded, transmitted, or shared by the app. It stays in the files you chose and in the app’s own local data on your device (for example, remembering the last few track/session combinations you’ve built, so you can reopen them without re-picking files).

03 The optional AI coaching feature

If you turn on AI coaching, PDR Viewer sends a compact, derived summary of your lap analysis — lap times, corner names, speeds, and similar performance numbers — to a provider you choose, so it can write a short coaching narrative back. This summary never includes raw video, GPS coordinates, or file names. Where that summary goes depends on which provider you pick:

CLOUD PROVIDERS

Anthropic, OpenAI, or Google Gemini. Your device sends the lap summary directly to that provider’s own servers, using an API key you supply and manage yourself. That exchange is covered by the provider’s own privacy policy and terms, not this one.

OLLAMA

Runs against a language model on your own computer or local network. Nothing leaves your local network.

APPLE INTELLIGENCE

Processed entirely on-device using Apple’s on-device model. No network request is made at all.

AI coaching is off unless you turn it on, and you can turn it back off at any time in Settings.

04 API keys and credentials

Any API key you enter for a cloud coaching provider is stored in your device’s Keychain, the same secure storage macOS and iOS use for passwords. It’s used only to authenticate your own requests to that provider and is never sent anywhere else, including to the developer of this app.

05 App preferences and local storage

Browsing community track maps fetches a public list of track files from GitHub. That request sends no personal information — it's an ordinary download of a public file. Submitting a track of your own is always initiated by you, and you choose what name and credit to include.

Settings like your chosen units, language, coaching provider, and recently used track/session files are stored locally on your device so the app remembers them between launches. None of this is synced to a server or shared with anyone.

06 Bug reports you choose to send

The app can generate a diagnostic report to help track down a problem. Nothing is collected or transmitted automatically — a report is only created when you ask for one, and only leaves your device if you choose to send it.

A report contains your app and OS version, the app’s current state (which track and session files are selected, lap counts and times), the folder locations of your track and session libraries, and anything you type into the description box. Because those folder paths are shown in full, they may include your computer’s account name. If you’d rather not share that, you can edit the report file before sending it, or describe the problem in an email without attaching it.

If you leave “Include current lap data” checked, the report also contains the decoded telemetry for the laps currently loaded — lap times, speed, braking, and GPS coordinates from those laps. Uncheck it if you don’t want that included.

Reports are sent by you, to the developer, using whatever method you pick (email, AirDrop, or a public issue tracker). Anything you attach to a public issue tracker is publicly visible; email is private. Reports are used only to diagnose the problem you reported.

07 What this app doesn’t do

  • No accounts, sign-in, or user profiles.
  • No analytics, crash reporting, or advertising SDKs.
  • No access to your device’s live location — GPS coordinates only ever come from telemetry files you choose to open.
  • No selling or sharing of data for advertising or marketing purposes.
